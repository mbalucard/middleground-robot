# 库存查询

工具：`get_inventory_data`

查商品库存。默认按商品汇总。仓库 ID 来自 `get_warehouse_info`，商品编码来自 `get_goods_info`。用户给了门店名或药名、还没有这两个值时，先按 `/skills/erp-stock/SKILL.md` 去查，不要用门店名或药名直接调本工具。

用户没指定门店或仓库、只问某种商品一共还有多少时，可以不传 `warehouse_id`。

## 参数

| 参数 | 含义 | 默认 | 取值 |
| --- | --- | --- | --- |
| `is_summary` | 是否汇总 | `True` | `True` 按商品汇总。`False` 查明细 |
| `tenant_id` | 租户 ID | 无 | 查过仓库时用结果里的「租户ID」，整数。没查仓库时不传 |
| `warehouse_id` | 仓库 ID 列表 | `[]` | 字符串列表，元素是「仓库ID」。不限定仓库时保持 `[]` |
| `goods_codes` | 商品编码列表 | `[]` | 字符串列表，元素是「商品编码」。与助记码至少传一个 |
| `goods_mnemonic_code` | 商品助记码 | 无 | 模糊匹配，必须大写。使用时还必须传 `warehouse_id` |
| `shop_type` | 门店范围 | `[]` | 见下方规则 |
| `current` | 页码 | `1` | 正整数 |
| `size` | 每页条数 | `20` | 正整数 |

`shop_type`：

- `[]`：总部、直营、加盟一起查。总部是连锁仓库或批发公司仓库。这是默认值。
- `["1"]`：只查直营店。
- `["2"]`：只查加盟店。
- `["1","2"]`：直营和加盟一起查，不含总部。

什么时候改 `shop_type`：

- 用户没限定范围，或已经用 `warehouse_id` 指定了某一家：保持 `[]`。指定了门店也不要改成 `["1"]`。
- 用户只说「只看门店」，没说直营还是加盟：传 `["1"]`。
- 用户说「所有门店」或「全部门店」：传 `["1","2"]`。
- 用户明确只看直营：传 `["1"]`。明确只看加盟：传 `["2"]`。
- 只要不是 `[]`，回答时说明不含总公司仓库。只查直营时同时说明不含加盟；只查加盟时同时说明不含直营。

`is_summary`：

- 默认 `True`。用户问「还有多少」「一共多少」，包括指定了某一家门店，都用汇总。
- 只有用户明确要明细，或要批号、每个仓库各多少、供应商时，才传 `False`。
- 用户要看各个门店分别多少，且没说只看直营或加盟：`is_summary=False`，`shop_type=["1","2"]`。
- 用户要看各个仓库分别多少，范围含总部：`is_summary=False`，`shop_type=[]`。

约束：

- 每次查询至少带一个商品条件：`goods_codes` 或 `goods_mnemonic_code`。两个都不传就不要调用。
- 用 `goods_mnemonic_code` 时，还必须传 `warehouse_id`。没有仓库 ID 时，先按 `SKILL.md` 用 `get_warehouse_info` 查到再来。助记码是大写首字母，传入前转成大写。
- 已经有商品编码时传 `goods_codes`，不要再传助记码。`goods_codes` 和 `warehouse_id` 都是列表，单个值也写成 `["code"]`、`["id"]`。
- 仓库 ID 必须来自 `get_warehouse_info` 里未被忽略的仓库。名称含「物资」的仓库默认不能拿来查，除非用户点名要查物资仓。汇总查询本身不要再为了排除物资仓去改 `warehouse_id`。
- 没有结果时不要改 `shop_type` 重试。`[]` 已经包含直营和加盟。

## 调用流程

1. 确认商品条件已经有了：商品编码，或「助记码 + 仓库ID」。缺商品条件时先去查商品，不要空查库存。用助记码但没有仓库 ID 时，先查仓库。
2. 决定 `is_summary`。没明确要明细就用 `True`。
3. 决定 `shop_type`。默认 `[]`。按上面的规则，只有用户限定了门店范围才改。
4. 调用 `get_inventory_data`。
5. 看 `status`、`data`、`total_summary`、`page_info`。
6. 用中文整理库存。合计用 `total_summary`，不要把当前页记录加总当成全部。用户要完整结果且 `page_info.pages` 大于当前页时，递增 `current` 继续查。
7. 按实际使用的 `shop_type` 说明范围。`[]` 说明含总部、直营、加盟。其他取值说明不含总公司仓库。

## 返回结构

成功：`status` 为 `success`。

- `data`：库存列表，字段是中文。汇总和明细的列不同
- `total_summary`：本次查询的合计，对应接口里的 `totalSummary`。回答「一共还有多少」时用这里的数量，不要只加总当前页
- `page_info`：`current` / `size` / `pages` / `total`

`total_summary` 的字段是英文，只有下面这些，不要编造其它键：

| 字段 | 含义 |
| --- | --- |
| `index` | 固定为「合计」 |
| `stockQty` | 库存数量 |
| `availableStockQty` | 可用库存数量。回答「还有多少」时用这个 |
| `stockQtyInway` | 在途库存数量。采购订单已做、尚未入库 |
| `lockQty` | 占用库存。销售订单已做、尚未出库 |
| `stockCost` | 库存成本额。仅用户问成本时展示 |

无数据：`status` 为 `error`，`message` 为「未找到库存数据」。直接说明这个范围没有库存记录。不要改 `shop_type` 或 `is_summary` 再查一遍，也不要说系统故障。

未授权：`message` 为「未授权」。直接告诉用户，不要改参数再试。

### 汇总（`is_summary=True`）

一条记录是一个商品，没有门店、批号、供应商。指定了仓库时，仓库名用前面 `get_warehouse_info` 的结果，不要从库存行里找。

| 字段 | 含义 |
| --- | --- |
| `商品编码` | 核对是否查对商品 |
| `通用名称` | 药名 |
| `商品名称` | 商品名 |
| `规格/型号` | 规格 |
| `基本单位` | 数量单位 |
| `剂型` | 剂型 |
| `批准文号` | 批准文号 |
| `条形码` | 商品条形码 |
| `生产企业` | 厂家 |
| `库存数量` | 账面库存 |
| `可用库存数量` | 可用库存 |
| `在途库存数量` | 已经做了采购订单、但还没有入库的数量 |
| `占用库存` | 已经做了订单但还没有出库的数量。订单包括批发销售单、零售销售单；未出库指批发还没做销售出库，或零售 POS 还没下账 |
| `成本单价` | 平均成本单价。仅用户问成本时展示 |
| `库存成本额` | 库存成本金额。仅用户问成本时展示 |
| `商品类型` | 商品类型 |
| `所属分类` | 商品分类 |
| `进口药品` | 是否进口药品 |
| `是否拆零` | 该商品是不是拆零商品。值为「是」时可以拆开卖。例如一大包三黄片里有 50 小包，原来库存 1 包，卖出 10 小包后，库存数量变成 0.8 包 |

先报 `total_summary` 里的可用库存、库存数量、在途和占用，再列商品。不要报批号。

### 明细（`is_summary=False`）

一条记录是一个仓库里的一个批号。同一商品多条记录通常是不同批号，或不同仓库。

| 字段 | 含义 |
| --- | --- |
| `门店/仓库编码` | 库存所在门店或仓库的编码 |
| `仓库ID` | 核对是否查对仓库 |
| `门店类型` | 直营或加盟 |
| `门店/仓库名称` | 库存所在仓库 |
| `门店/仓库简称` | 短名 |
| `商品编码` | 核对是否查对商品 |
| `通用名称` | 药名 |
| `商品名称` | 商品名 |
| `规格/型号` | 规格 |
| `基本单位` | 数量单位 |
| `剂型` | 剂型 |
| `批准文号` | 批准文号 |
| `批号` | 生产厂家的生产批次，不是门店、连锁或批发自己的批次 |
| `条形码` | 商品条形码 |
| `生产企业` | 厂家 |
| `库存数量` | 账面库存 |
| `可用库存数量` | 本条明细的可用库存 |
| `在途库存数量` | 已经做了采购订单、但还没有入库的数量 |
| `占用库存` | 已经做了订单但还没有出库的数量 |
| `成本单价` | 平均成本单价，等于本条的库存成本额除以库存数量。仅用户问成本时展示 |
| `库存成本额` | 本条库存的成本金额。仅用户问成本时展示 |
| `商品类型` | 商品类型 |
| `所属分类` | 商品分类 |
| `供应商编码` | 供应商编码 |
| `供应商名称` | 供应商名称 |
| `是否拆零` | 该商品是不是拆零商品 |
| `进口药品` | 是否进口药品 |

先报 `total_summary` 里的可用库存、库存数量、在途和占用，再按仓库和批号列明细。明细只是当前页，和合计不一致时以合计为准，并说明是否还有下一页。

## 示例

已经得到租户 `1`、仓库 `WH001`、商品编码 `10001234`。用户问这家还有多少，走汇总，门店范围保持默认：

```
get_inventory_data(tenant_id=1, warehouse_id=["WH001"], goods_codes=["10001234"])
```

用户没指定门店，问这个商品一共还有多少：

```
get_inventory_data(goods_codes=["10001234"])
```

用户说只看门店，或明确只看直营：

```
get_inventory_data(goods_codes=["10001234"], shop_type=["1"])
```

用户说所有门店：

```
get_inventory_data(goods_codes=["10001234"], shop_type=["1", "2"])
```

用户明确只看加盟：

```
get_inventory_data(goods_codes=["10001234"], shop_type=["2"])
```

用户要这个商品的批号明细：

```
get_inventory_data(tenant_id=1, warehouse_id=["WH001"], goods_codes=["10001234"], is_summary=False)
```

用户给了助记码 `LWDHW`，并且已经有仓库 `WH001`：

```
get_inventory_data(tenant_id=1, warehouse_id=["WH001"], goods_mnemonic_code="LWDHW")
```

用户点名要查物资仓，并且已经得到它的仓库 ID `MAT001`：

```
get_inventory_data(tenant_id=1, warehouse_id=["MAT001"], goods_codes=["10001234"])
```
