# 库存盘点查询

工具：`get_inventory_audit_summary_data`

查库存盘点的门店汇总或商品汇总。默认按门店汇总、只看直营、只看产生盈亏的记录。仓库 ID 来自 `get_warehouse_info`，商品编码来自 `get_goods_info`。用户给了门店名或药名、还没有这两个值时，先按 `/skills/erp-stock/SKILL.md` 去查，不要用门店名或药名直接调本工具。

本工具的门店范围参数叫 `store_type`，不要和库存工具的 `shop_type` 混用。默认也不同：盘点默认只查直营 `["1"]`，库存默认是 `[]`。

## 参数

| 参数 | 含义 | 默认 | 取值 |
| --- | --- | --- | --- |
| `start_date` | 制单开始日期 | 必填 | `YYYY-MM-DD` |
| `end_date` | 制单结束日期 | 必填 | `YYYY-MM-DD` |
| `is_store_summary` | 是否按门店汇总 | `True` | `True` 按门店。`False` 按商品 |
| `tenant_id` | 租户 ID | 无 | 查过仓库时用结果里的「租户ID」，整数。没查仓库时不传 |
| `warehouse_id` | 仓库 ID 列表 | `[]` | 字符串列表，元素是「仓库ID」。不限定仓库时保持 `[]` |
| `goods_codes` | 商品编码列表 | `[]` | 字符串列表，元素是「商品编码」。不限定商品时保持 `[]` |
| `store_type` | 门店范围 | `["1"]` | 见下方规则 |
| `is_profit_loss` | 是否产生盈亏 | `["是"]` | `是` / `否`。与 `profit_loss_status` 互斥 |
| `profit_loss_status` | 盈亏状态 | `[]` | `不盈不亏` / `盘盈` / `盘亏`。与 `is_profit_loss` 互斥 |
| `take_stock_type` | 盘点类型 | `[]` | `1` 抽盘，`2` 全盘。用户不说时保持 `[]` |
| `current` | 页码 | `1` | 正整数 |
| `size` | 每页条数 | `20` | 正整数 |

### 日期

起止日期都必填。相对日期先调用 `get_current_date`，用返回字符串开头的日期，不要沿用本轮更早的日期。

- 用户没说日期，或说「最近」：本月 1 日到本月最后一天。
- 本月：本月 1 日到本月最后一天。
- 上月：上月 1 日到上月最后一天。
- 用户给了明确起止：按用户说的日期。

回答第一句写明实际查询的日期范围。

### `is_store_summary` 与 `size`

- 默认 `True`：按门店汇总。看各店盘点情况、整体盈亏、盘点品相数时用这个。
- `False`：按商品汇总。看哪些货盘盈盘亏、某商品盘点结果时用这个。两种结果都带「门店类型」分组。
- 用户同时点了门店和商品：`False`，并带上 `warehouse_id` 与 `goods_codes`。
- 用户说「一共」「整体」等、但没说不要列表：仍按默认列当前页；`page_info.total > 1` 时在末尾再报 `total_summary`。
- **只有**用户明确说「只看合计」「只要合计」「不要明细/列表」时：`is_store_summary=True`，`size=1`，只报 `total_summary`，不展示 `data`。未这样说时不要用 `size=1`。

### `store_type`

- `["1"]`：只查直营。这是默认值。用户没限定范围时保持这个。
- `["2"]`：只查加盟。
- `["1","2"]`：直营和加盟一起查，不含总部。
- `[]`：总部、直营、加盟一起查。总部是连锁仓库或批发公司仓库（「仓库类型」多为「企业仓库」）。

什么时候改 `store_type`：

- 用户没限定范围：保持 `["1"]`。
- 已经用 `warehouse_id` 指定了某一家（含总部仓）：传 `[]`。不要因为这是门店就改成 `["1"]`。
- 用户说「所有门店」或「全部门店」：传 `["1","2"]`。
- 用户明确只看直营：`["1"]`。明确只看加盟：`["2"]`。
- 用户明确要查总部、连锁仓、批发仓：先用 `get_warehouse_info` 拿到总部仓的「仓库ID」，放入 `warehouse_id`，`store_type` 传 `[]`。总部仓名称里通常带「仓」字，「仓库类型」一般是「企业仓库」，不是「门店仓」。名称含「物资」的仍默认不用，除非用户点名。
- 只要不是默认直营，回答时说明实际范围。`["1","2"]` 说明不含总公司仓库；只查直营时说明不含加盟；只查加盟时说明不含直营。

不要因为直营没有结果，再自动改成加盟或 `[]` 重查。

### 盈亏筛选（互斥）

`is_profit_loss` 与 `profit_loss_status` 只能用一边，另一边必须是 `[]`。

一般情况下只用 `is_profit_loss`：

- 默认 `is_profit_loss=["是"]`，`profit_loss_status=[]`：只看产生盈亏的。
- 用户说「有没有盈亏都要看」「全部盘点」「含不盈不亏」：`is_profit_loss=[]`，`profit_loss_status=[]`。
- 用户只要无盈亏：`is_profit_loss=["否"]`，`profit_loss_status=[]`。

只有用户明确只要某一种盈亏状态时，才改用 `profit_loss_status`，同时把 `is_profit_loss` 置为 `[]`：

- 只看盘盈：`profit_loss_status=["盘盈"]`
- 只看盘亏 / 盘损：`profit_loss_status=["盘亏"]`（口语「盘损」映射为「盘亏」）
- 只看不盈不亏：`profit_loss_status=["不盈不亏"]`

### `take_stock_type`

用户不提抽盘、全盘时，保持 `[]`。只有用户明确说抽盘或全盘时才传 `["1"]` 或 `["2"]`。

### 约束

- `goods_codes` 和 `warehouse_id` 都是列表，单个值也写成 `["code"]`、`["id"]`。
- 仓库 ID 必须来自 `get_warehouse_info`。名称含「物资」的仓库默认不能拿来查，除非用户点名。
- 商品编码必须来自 `get_goods_info`。不要把药名直接塞进 `goods_codes`。
- 没有结果时不要改 `store_type`、`is_profit_loss` 或日期范围自动重试。

## 调用流程

1. 定日期。没说日期或说最近，用当月 1 日到当月最后一天。
2. 需要门店或总部仓时，先读 `/skills/erp-stock/warehouse.md` 拿到「仓库ID」「租户ID」。
3. 需要商品时，先读 `/skills/erp-stock/goods.md` 拿到「商品编码」。
4. 决定 `is_store_summary`。默认 `True`；看商品维度或同时点了门店+商品时用 `False`。
5. 决定 `store_type`。默认 `["1"]`；已用 `warehouse_id` 限定时改为 `[]`。
6. 决定盈亏筛选。默认只用 `is_profit_loss=["是"]`。
7. `take_stock_type` 保持 `[]`，除非用户点名抽盘或全盘。
8. 决定 `size`。默认 `20`。仅用户明确只要合计时用 `1`。
9. 调用 `get_inventory_audit_summary_data`。
10. 看 `status`、`message`、`data`、`total_summary`、`page_info`。用中文整理。
11. `size=1` 且只要合计：只整理 `total_summary`。否则先列当前页；仅当 `page_info.total > 1` 时，在表格或列表**最下面**再报 `total_summary` 里与本次已展示明细字段对应的项。`total` 为 `1` 时不报合计。
12. 用户要完整结果且 `page_info.pages` 大于当前页时，递增 `current` 继续查。
13. 按实际使用的 `store_type` 和日期说明范围。

## 返回结构

有数据：`status` 为 `success`，带 `data`、`total_summary`、`page_info`。

- `data`：当前页明细，字段是中文
- `total_summary`：本次查询**全部命中行**的合计，是接口处理好的结果，不是把当前页或各店数字简单相加。例如各店「盘点品相数」相加会重复同一商品编码，合计里的「盘点品相数」是去重后的。回答合计时必须用这里的值，不要自己加总 `data`
- `page_info`：`current` / `size` / `pages` / `total`。是否报合计看 `total`，不是看当前页条数

无数据：`status` 仍为 `success`，`message` 为「未找到库存盘点数据」。直接说明这个日期和范围内没有盘点记录。不要改参数重查，也不要说系统故障。

未授权：`message` 为「未授权」。直接告诉用户，不要改参数再试。

### 合计（`total_summary`）

`total_summary` 是单个 dict（中文字段），不是列表。按门店汇总与按商品汇总字段不同。

**何时报：**

- `page_info.total > 1`：列完当前页后，在最下面报合计
- `page_info.total` 为 `1`：不报合计
- 用户明确只要合计且 `size=1`：只报合计，不展示 `data`

**报哪些字段：** 跟随本次回答里已经展示的明细字段；明细展示了某指标，且 `total_summary` 里有对应项，就一并报。不要报明细里没展示的项。不要编造 `total_summary` 没有的键。

明细与合计字段对应（名称不完全相同的以对应关系为准）：

| 明细字段 | 合计字段 |
| --- | --- |
| `账面库存` | `账面库存数量` |
| `出库数量` | `出库数量` |
| `入库数量` | `入库数量` |
| `盘点数量` | `盘点数量` |
| `盈亏数量` | `盈亏数量` |
| `盈亏成本额` | `盈亏成本额` |
| `盈亏状态` | `盈亏状态`（仅按门店汇总的合计有） |
| `盘点品相数` | `盘点品相数`（仅按门店汇总的合计有；去重后的品项数） |
| `账面库存成本额` | `账面库存成本额`（仅按门店汇总的合计有） |
| `盘点库存成本额` | `盘点库存成本额`（仅按门店汇总的合计有） |

按默认展示时，按门店汇总在 `total > 1` 下应报的合计通常是：盘点品相数、账面库存数量、盘点数量、盈亏数量、盈亏成本额、盈亏状态。按商品汇总通常是：账面库存数量、盘点数量、盈亏数量、盈亏成本额（商品合计没有盈亏状态、盘点品相数）。成本两项仍仅用户问成本、且明细已展示时才从合计里带上。

### 按门店汇总（`is_store_summary=True`）

一条记录是一家门店或仓库的盘点汇总。没有商品明细。

| 字段 | 含义 |
| --- | --- |
| `门店类型` | 直营或加盟等 |
| `区域ID` | 区域标识 |
| `直属区域` | 区域名称 |
| `门店/仓库编码` | 编码 |
| `仓库ID` | 本行对应仓库。用户追问这家店时，直接拿来传 `warehouse_id`，不必再调 `get_warehouse_info` |
| `门店/仓库名称` | 名称 |
| `门店/仓库简称` | 短名 |
| `盘点品相数` | 本次盘点涉及的品项数 |
| `账面库存` | 盘点时的账面数量 |
| `出库数量` | 出库数量 |
| `入库数量` | 入库数量 |
| `盘点数量` | 实盘数量 |
| `盈亏数量` | 盘点相对账面的盈亏数量 |
| `账面库存成本额` | 账面成本。仅用户问成本时展示 |
| `盘点库存成本额` | 实盘成本。仅用户问成本时展示 |
| `盈亏成本额` | 盈亏对应的成本额。默认展示 |
| `盈亏状态` | 盘盈 / 盘亏 / 不盈不亏 这里的盈亏指的是盈亏成本额的盈亏状态，而非盈亏数量的状态 |

默认展示：门店名称或简称、盘点品相数、账面库存、盘点数量、盈亏数量、盈亏成本额、盈亏状态。`仓库ID` 默认不展示给用户，但要记住；用户追问「这家店」「某某店再看看商品」时，把该行的「仓库ID」放进 `warehouse_id`，`store_type` 改为 `[]`，需要商品明细时再把 `is_store_summary` 改为 `False`。不要为已出现在结果里的店再调一次 `get_warehouse_info`。账面库存成本额、盘点库存成本额仅用户问成本时展示。

`page_info.total > 1` 时，在列表最下面用 `total_summary` 报与上述已展示字段对应的合计（见上方「合计」）。不要把各店盘点品相数相加当成全部品相数。

### 按商品汇总（`is_store_summary=False`）

一条记录是一个商品在某一门店类型下的盘点汇总。没有具体门店名称；同一商品在直营、加盟下可能各有一行。

| 字段 | 含义 |
| --- | --- |
| `门店类型` | 直营或加盟等 |
| `商品编码` | 核对是否查对商品 |
| `通用名称` | 药名 |
| `商品名称` | 商品名 |
| `规格/型号` | 规格 |
| `剂型` | 剂型 |
| `基本单位` | 数量单位 |
| `批准文号` | 批准文号 |
| `生产企业` | 厂家 |
| `所属分类` | 商品分类 |
| `账面库存` | 盘点时的账面数量 |
| `出库数量` | 出库数量 |
| `入库数量` | 入库数量 |
| `盘点数量` | 实盘数量 |
| `盈亏数量` | 盈亏数量 |
| `盈亏成本额` | 盈亏对应的成本额。默认展示 |
| `盈亏状态` | 盘盈 / 盘亏 / 不盈不亏 |

默认展示：商品编码、通用名称、规格、账面库存、盘点数量、盈亏数量、盈亏成本额、盈亏状态。

`page_info.total > 1` 时，在列表最下面用 `total_summary` 报对应合计。商品合计没有「盈亏状态」「盘点品相数」，有则报、无则跳过。

## 示例

用户没说日期，问直营店最近盘点盈亏情况（默认当月、按门店、只看有盈亏）。列当前页；`page_info.total > 1` 时再报合计：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31")
```

用户明确只要合计、不要列表：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31", size=1)
```

用户说所有门店本月盘点：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31", store_type=["1", "2"])
```

用户要看有没有盈亏都算上的全部盘点：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31", is_profit_loss=[])
```

用户只要盘亏（或说盘损）：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31", is_profit_loss=[], profit_loss_status=["盘亏"])
```

已经得到商品编码 `10001234`，问这个商品本月盘点盈亏：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31", goods_codes=["10001234"], is_store_summary=False)
```

已经得到租户 `1`、仓库 `WH001`、商品编码 `10001234`，问这家这个商品的盘点：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31", tenant_id=1, warehouse_id=["WH001"], goods_codes=["10001234"], store_type=[], is_store_summary=False)
```

已经得到总部仓仓库 ID `DC001`、租户 `1`，查总部本月盘点：

```
get_inventory_audit_summary_data(start_date="2026-10-01", end_date="2026-10-31", tenant_id=1, warehouse_id=["DC001"], store_type=[])
```
