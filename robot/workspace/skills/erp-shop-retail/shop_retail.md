# 门店零售查询

工具：`get_shop_retail_info`

查门店在一段日期内的零售汇总（门店维度，不按商品拆）。一家店在整个日期区间里只有一行，行内数字是这段时间的合计，不是某一天，也不是单笔小票。

要看某个商品卖了多少，不要用本工具，改读 `/skills/erp-shop-retail/goods_retail.md`，用 `get_store_goods_retail_info`。本工具不能传商品编码。

没点名门店、还没有门店编码时，按 `/skills/erp-shop-retail/SKILL.md` 决定是汇总还是明细。用户给了门店名、还没有编码时，先读 `/skills/erp-shop-retail/shop.md` 调用 `get_shop_available_info`，不要用门店名直接调本工具。用户给了区域名、还没有区域 ID 时，先读 `/skills/erp-shop-retail/region.md` 调用 `get_region_tree_info`，不要用区域名直接调本工具。

总部没有零售。不要传仓库 ID。

## 参数

| 参数 | 含义 | 默认 | 取值 |
| --- | --- | --- | --- |
| `start_date` | 开始日期 | 必填 | `YYYY-MM-DD` |
| `end_date` | 结束日期 | 必填 | `YYYY-MM-DD` |
| `store_code` | 门店编码列表 | `[]` | 字符串列表，元素是「门店编码」。不限定门店时保持 `[]` |
| `store_type` | 门店类型 | `[]` | 见下方规则 |
| `tenant_id` | 租户 ID | 无 | 查过门店时用结果里的「租户ID」，整数。没有时不传 |
| `region_id` | 区域 ID 列表 | `[]` | 字符串列表，元素是区域树里的「区域ID」。不要转成整数。不按区域查时保持 `[]` |
| `current` | 页码 | `1` | 正整数 |
| `size` | 每页条数 | 工具默认 `20`，不要用 | 汇总传 `1`，明细传 `10` |

`size` 和没点名时的 `store_type` 都必须显式传入。

日期按 `SKILL.md` 换算。用户没说日期时，开始和结束都是 `get_current_date` 返回的当天。

`store_code`：

- 点名了一家或多家，并且已经有编码：放进同一个列表，例如 `["1001","1002"]`。同一时段只调用一次。
- 没点名门店：保持 `[]`。
- 单个编码也写成 `["1001"]`。不要传门店名称，不要传仓库 ID。

`store_type`：

- 已经传了 `store_code`：保持 `[]`。不要因为这家店是直营就再传 `["1"]`。
- 已经传了 `region_id`，用户没说直营还是加盟：传 `[]`，直营和加盟一起查。
- 没点名门店，也没点名区域，也没说直营还是加盟：传 `["1"]`，只查直营。不要省略。省略后代码默认是 `[]`，会把直营和加盟查在一起。
- 明确只看直营：传 `["1"]`。明确只看加盟：传 `["2"]`。
- 直营和加盟都要：传 `[]`。

`region_id`：

- 没点名区域：保持 `[]`。
- 点名了区域：传入 `region.md` 收集到的全部字符串 ID。包含选定区域自己，以及下面所有状态正常的下级，直到 `是否子节点` 为 `true` 的叶子。根区域（层级 `0`）自己的 ID 也要放进去。单个值也写成 `["101"]`，不要写成 `[101]`。
- 点名了具体门店：保持 `[]`，只用 `store_code`。不要和 `region_id` 一起传。
- 不要用门店结果里的单个「区域ID」代替这套收集结果。

`size`：

- 汇总：`1`。用于「整体」「各门店」、以及没点名且没说「分别」的查询。只为了拿到全部页的 `total_summary`，不要展示 `data` 里的那一行。
- 明细：`10`。用于点名门店，或用户说「分别」。
- 不要一次把 `size` 调大。用户要下一页时，`current` 加 1，`size` 仍为 `10`。

没有结果时不要改 `store_type`、`region_id` 或 `size` 重试。不要把区域改写成一批门店编码再查。

## 调用流程

1. 确认 `start_date` 和 `end_date`。没说日期就用当天，调用前先取 `get_current_date`。
2. 确认有没有门店编码。有门店名称没有编码时，先查门店。
3. 确认有没有区域 ID。有区域名称没有 ID 时，先查区域树，并按 `region.md` 收齐 ID。点了具体门店就不要再传 `region_id`。
4. 按上面的规则定 `store_type`。点了门店，或点了区域但没说直营加盟，都保持 `[]`。
5. 汇总传 `size=1`，明细传 `size=10`。
6. 调用 `get_shop_retail_info`。
7. 看 `status`、`data`、`total_summary`、`page_info`。
8. 汇总只整理 `total_summary`。明细先报合计，再列当前页门店行。

对比两个时段时，用同一套 `store_code`、`store_type`、`region_id` 和 `size` 各查一次，只更换日期。

## 返回结构

成功：`status` 为 `success`。

- `data`：当前页的门店列表。一家店一行，字段是中文
- `total_summary`：本次查询全部页的合计，对应接口里的 `totalSummary`。回答合计时用这里的数，不要只加总当前页
- `page_info`：`current` / `size` / `pages` / `total`

`page_info.total` 是符合条件的门店数。`data` 只是当前页。汇总查询即使 `size=1`，`total_summary` 仍是全部门店的合计。

无数据：`status` 为 `error`，`message` 为「未找到门店零售信息」。直接说明这个日期和范围没有零售记录。不要改 `store_type` 再查，也不要说系统故障。

未授权：`message` 为「未授权」。直接告诉用户，不要改参数再试。

日期范围写在回答顶部。结果里没有日期字段。区间里有销售的天数看「动销天数」，它不是日历天数。用户要每一天的数时，说明这里只有区间汇总，不要按天拆开重查。

### 门店行（`data`）

「门店类型」可能仍是 `1` 或 `2`。回答时 `1` 写成直营，`2` 写成加盟。已经是中文就原样使用。

明细默认只展示这些列：

| 字段 | 含义 |
| --- | --- |
| `门店编码` | 核对是否查对门店 |
| `门店简称` | 展示 |
| `门店类型` | 直营或加盟 |
| `应收金额` | 应收 |
| `实收金额` | 实收 |
| `折扣率` | 折扣率 |
| `毛利率` | 毛利率 |
| `交易次数` | 交易次数 |
| `客单价` | 实收金额 / 交易次数 |
| `客品数` | 销售数量 / 交易次数 |

用户问到对应内容时，再使用其余字段：

| 字段 | 含义 |
| --- | --- |
| `门店名称` | 全称 |
| `销售数量` | 销售数量 |
| `成本额` | 成本。仅用户问成本时展示 |
| `折扣金额` | 折扣金额 |
| `毛利额` | 毛利额。仅用户问毛利额时展示 |
| `品单价` | 实收金额 / 销售数量 |
| `客品次` | 客品次 |
| `会员交易次数` | 会员交易次数 |
| `会员交易次数占比` | 会员交易次数 / 交易次数 |
| `会员实收金额` | 会员实收金额 |
| `会员销售占比` | 会员实收金额 / 实收金额 |
| `动销品项数` | 动销品项数 |
| `库存品项数` | 库存品项数 |
| `动销率` | 动销品项数 / 库存品项数 |
| `动销天数` | 这段日期里有销售的天数 |
| `日均实收金额` | 实收金额 / 期间天数 |
| `日均毛利额` | 毛利额 / 期间天数 |
| `日均交易次数` | 交易次数 / 期间天数 |

### 合计（`total_summary`）

一个字典，没有门店编码、门店名称、门店简称、门店类型。汇总回答默认只报：

| 字段 | 含义 |
| --- | --- |
| `应收金额` | 应收 |
| `实收金额` | 实收 |
| `折扣率` | 折扣率 |
| `毛利率` | 毛利率 |
| `交易次数` | 交易次数 |
| `客单价` | 客单价 |
| `客品数` | 客品数 |

其余字段与门店行里的金额、会员、动销、日均相同，只在用户问到时展示。合计里也有「动销天数」。

比率和单价以 `total_summary` 里的值为准，不要用当前页自己重算。

## 示例

用户没点名门店，问今天零售怎么样。先取当前日期，再只查直营合计：

```
get_shop_retail_info(start_date="2026-10-20", end_date="2026-10-20", store_type=["1"], size=1)
```

用户没点名，明确要加盟：

```
get_shop_retail_info(start_date="2026-10-20", end_date="2026-10-20", store_type=["2"], size=1)
```

用户没点名，直营和加盟都要：

```
get_shop_retail_info(start_date="2026-10-20", end_date="2026-10-20", store_type=[], size=1)
```

用户说「直营店分别多少」，给明细：

```
get_shop_retail_info(start_date="2026-10-20", end_date="2026-10-20", store_type=["1"], size=10)
```

已经得到租户 `1`、门店编码 `1001` 和 `1002`。用户问这两家本月的零售：

```
get_shop_retail_info(start_date="2026-10-01", end_date="2026-10-20", store_code=["1001", "1002"], tenant_id=1, size=10)
```

用户要这两家和上月比。再查一次，只改日期：

```
get_shop_retail_info(start_date="2026-09-01", end_date="2026-09-30", store_code=["1001", "1002"], tenant_id=1, size=10)
```

已经从区域树收集到「西南区」及其正常下级的区域 ID `"101"`、`"102"`、`"103"`。用户没说分别，查这个区域的合计，直营和加盟一起：

```
get_shop_retail_info(start_date="2026-10-20", end_date="2026-10-20", region_id=["101", "102", "103"], store_type=[], size=1)
```

用户要这个区域的门店分别多少：

```
get_shop_retail_info(start_date="2026-10-20", end_date="2026-10-20", region_id=["101", "102", "103"], store_type=[], size=10)
```
