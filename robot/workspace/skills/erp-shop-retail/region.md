# 区域查询

工具：`get_region_tree_info`

查区域树。按区域查零售时，`region_id` 从这里收集。这个工具没有关键词，一次返回整棵树压平后的全部区域，没有分页。

区域层级为 `0` 的是根区域。`是否子节点` 为 `true` 时，该区域下面没有下级。

状态为「停用」的区域什么时候都不选。用户点名的就是停用区域时，直接说明该区域已停用，无法查询，不要继续查零售，也不要改用它的下级。

## 参数

| 参数 | 含义 | 默认 | 取值 |
| --- | --- | --- | --- |
| `tenant_id` | 租户 ID | 无 | 已经从门店结果拿到「租户ID」时传整数。不确定时不传 |

## 调用流程

1. 调用 `get_region_tree_info`
2. 看 `status` 和 `data`
3. 用用户说的区域名称或区域编码，在 `data` 里找对应记录。名称先按「区域名称」精确匹配；对不上时再看包含这个名称的记录
4. 去掉「区域状态」为「停用」的记录
5. 剩下 0 条：若未过滤前只有停用记录，告诉用户该区域已停用，无法查询。若本来就没有这个名称，告诉用户没找到
6. 剩下多条：列出「区域名称」「区域层级」「父区域名称」「区域ID」，请用户选一条。不要自己挑
7. 剩下一条，并且后续要查零售：按下面的规则收集区域 ID

只问有哪些区域时，停在第 4 步。默认展示「区域名称」「区域层级」「父区域名称」。层级 `0` 说明这是根区域。停用的不列出。

## 收集区域 ID

从用户选定的那条开始，把它自己的「区域ID」放进列表。再沿着「父区域ID」往下找所有下级，直到 `是否子节点` 为 `true` 的叶子。叶子没有更下面的区域，叶子自己的 ID 也要放进去。

沿途「区域状态」为「停用」的 ID 不放进列表。停用节点下面如果还有状态正常的区域，那些正常区域的 ID 仍然收集。

根区域同样处理：层级 `0` 的根区域自己的 ID 要传，它下面所有正常区域的 ID 也要传。

用户一次说了多个区域：每个区域各收一套 ID，合并后放进同一次零售查询的 `region_id`。其中某个区域已停用时，告诉用户该区域无法查询，只用其余正常区域的 ID。

`region_id` 是字符串列表。从结果里取出的「区域ID」原样传入，不要转成整数，例如 `["101", "102", "103"]`。「父区域ID」也是字符串，对照上下级时按字符串比较。

## 返回结构

成功：`status` 为 `success`。列表在 `data`。没有 `page_info`。

无数据：`status` 为 `error`，`message` 为「未找到区域树信息」。

未授权：`message` 为「未授权」。直接告诉用户未授权，不要改参数再试。

`data` 每条记录包含下面全部字段，顺序与 `region_tree_data_process` 的输出一致：

| 字段 | 用途 |
| --- | --- |
| `区域ID` | 放进门店零售或商品零售的 `region_id`。字符串 |
| `区域编码` | 用户给了编码时用来核对 |
| `区域层级` | `0` 是根区域。展示、消歧 |
| `区域名称` | 和用户说的区域名核对 |
| `区域状态` | 「正常」或「停用」。停用的不选 |
| `父区域ID` | 用来判断谁是谁的下级。字符串，不要转成整数 |
| `父区域名称` | 同名消歧、展示 |
| `是否子节点` | `true` 表示没有下级。收集 ID 时收到这一层为止 |

## 示例

用户：「有哪些区域」

```
get_region_tree_info()
```

用户要查「西南区」的零售。先拿区域树，找到「西南区」及其全部正常下级的区域 ID，再按 `shop_retail.md`（门店维度）或 `goods_retail.md`（商品维度）把这些 ID 传给 `region_id`。

用户点名的区域状态是「停用」：不要调用零售工具，直接说明该区域已停用，无法查询。
