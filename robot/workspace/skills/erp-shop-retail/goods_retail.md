# 门店商品零售查询

工具：`get_store_goods_retail_info`

按商品查一段日期内的零售。返回粒度是「门店 × 商品」一行：同一商品在三家店有销售，就会有三行。行内数字是整段日期的合计，不是某一天，也不是单笔小票。

`goods_code` 必填，禁止传 `[]`。没有商品编码时不要调本工具。

- 用户点了商品名、还没有编码：先读 `/skills/erp-stock/goods.md`，调用 `get_goods_info`。
- 用户点了门店名、还没有门店编码：先读 `/skills/erp-shop-retail/shop.md`，调用 `get_shop_available_info`。
- 用户点了区域名、还没有区域 ID：先读 `/skills/erp-shop-retail/region.md`，调用 `get_region_tree_info`。
- 用户点了门店、没点任何商品：不要用本工具，改读 `/skills/erp-shop-retail/shop_retail.md`，用 `get_shop_retail_info`，可告知「动销品项数」。
- 用户只问库存、不问销售：不要用本工具，走库存 skill。

总部没有零售。不要传仓库 ID。不做排名，不要翻页排序后宣布卖得最好。

## 参数

| 参数 | 含义 | 默认 | 取值 |
| --- | --- | --- | --- |
| `start_date` | 开始日期 | 必填 | `YYYY-MM-DD` |
| `end_date` | 结束日期 | 必填 | `YYYY-MM-DD` |
| `goods_code` | 商品编码列表 | 无，必填 | 字符串列表，元素是「商品编码」。至少一个。禁止 `[]` |
| `store_code` | 门店编码列表 | `[]` | 字符串列表。不限定门店时保持 `[]` |
| `store_type` | 门店类型 | `[]` | 见下方规则 |
| `tenant_id` | 租户 ID | 无 | 查过门店时用结果里的「租户ID」，整数。没有时不传 |
| `region_id` | 区域 ID 列表 | `[]` | 字符串列表，元素是区域树里的「区域ID」。不要转成整数。不按区域查时保持 `[]` |
| `current` | 页码 | `1` | 正整数 |
| `size` | 每页条数 | 工具默认 `20`，不要用 | 汇总传 `1`，明细传 `10` |

`goods_code`、`size`，以及没点名门店时的 `store_type`，都必须显式传入。

日期按 `SKILL.md` 换算。用户没说日期时，开始和结束都是 `get_current_date` 返回的当天。

`goods_code`：

- 必须来自用户已确认的商品，或用户直接给的编码。单个也写成 `["10001234"]`。
- 用户选定多个时，放进同一个列表，一次调用。不要替用户挑规格。
- 商品工具里的 `goods_codes` 是单个字符串；本工具的 `goods_code` 是列表。不要混用类型。
- 禁止空列表。禁止传商品名称、通用名。

`store_code`：

- 点名了一家或多家，并且已经有编码：放进同一个列表。同一时段只调用一次。
- 没点名门店：保持 `[]`。
- 不要传门店名称，不要传仓库 ID。

`store_type`：

- 已经传了 `store_code`：保持 `["1"]`。
- 已经传了 `region_id`，用户没说直营或加盟：传 `[]`，直营和加盟一起查。
- 没点名门店，也没点名区域，也没说直营还是加盟：传 `["1"]`，只查直营。不要省略。
- 明确只看直营：传 `["1"]`。明确只看加盟：传 `["2"]`。
- 直营和加盟都要：传 `[]`。

`region_id`：

- 没点名区域：保持 `[]`。
- 点名了区域：传入 `region.md` 收集到的全部字符串 ID。单个值也写成 `["101"]`，不要写成 `[101]`。
- 点名了具体门店：保持 `[]`，只用 `store_code`。不要和 `region_id` 一起传。

`size`：

- 汇总：`1`。用于点了商品、没点具体门店（含按区域），且没说「分别」：只采用 `total_summary`，不要展示 `data` 里那一行。
- 明细：`10`。用于点名门店，或用户说「分别」「各店」。
- 不要一次把 `size` 调大。用户要下一页时，`current` 加 1，`size` 仍为 `10`。

没有结果时不要改 `store_type`、`region_id`、`goods_code` 或 `size` 重试。

## 调用流程

1. 确认 `start_date` 和 `end_date`。没说日期就用当天，调用前先取 `get_current_date`。
2. 确认已有商品编码。没有则先按 `goods.md` 查商品；多条命中先让用户选（可选多条），不要代选。
3. 确认有没有门店编码。有门店名称没有编码时，先查门店。
4. 确认有没有区域 ID。有区域名称没有 ID 时，先查区域树并收齐 ID。点了具体门店就不要再传 `region_id`。
5. 按上面的规则定 `store_type`。
6. 汇总传 `size=1`，明细传 `size=10`。
7. 调用 `get_store_goods_retail_info`。
8. 看 `status`、`data`、`total_summary`、`page_info`。
9. 汇总只整理 `total_summary`。明细先报合计，再列当前页门店×商品行。

对比两个时段时，用同一套 `goods_code`、`store_code`、`store_type`、`region_id` 和 `size` 各查一次，只更换日期。

## 返回结构

成功：`status` 为 `success`。

- `data`：当前页的门店×商品列表。一行是一家店的一个商品，字段是中文
- `total_summary`：本次查询全部页的合计。回答合计时用这里的数，不要只加总当前页
- `page_info`：`current` / `size` / `pages` / `total`

`page_info.total` 是符合条件的行数（门店×商品）。汇总查询即使 `size=1`，`total_summary` 仍是全部行的合计。

无数据：`status` 为 `error`，`message` 为「未找到门店商品零售信息」。直接说明这个日期和范围没有该商品的零售记录。不要改参数再查，也不要说系统故障。

未授权：`message` 为「未授权」。直接告诉用户，不要改参数再试。

日期范围写在回答顶部。结果里没有日期字段。

### 门店×商品行（`data`）

「门店类型」可能仍是 `1` 或 `2`。回答时 `1` 写成直营，`2` 写成加盟。已经是中文就原样使用。

明细默认只展示这些列：

| 字段 | 含义 |
| --- | --- |
| `门店编码` | 核对门店 |
| `门店简称` | 展示 |
| `商品名称` | 展示 |
| `规格/型号` | 展示 |
| `销售数量` | 销售数量 |
| `实收金额` | 实收 |
| `毛利率` | 毛利率 |
| `门店库存` | 门店库存，默认展示 |

用户问到对应内容时，再使用其余字段：

| 字段 | 含义 |
| --- | --- |
| `门店名称` | 全称 |
| `门店类型` | 直营或加盟 |
| `商品编码` | 核对 |
| `通用名称` | 核对 |
| `基本单位` | 单位 |
| `剂型` | 展示 |
| `批准文号` | 核对 |
| `生产企业` | 核对 |
| `商品类型` | 展示 |
| `所属分类` | 展示 |
| `应收金额` | 应收 |
| `成本额` | 成本。仅用户问成本时展示 |
| `毛利额` | 毛利额。仅用户问毛利额时展示 |
| `交易次数` | 交易次数 |
| `总部库存` | 仅用户问总部库存时展示 |

### 合计（`total_summary`）

一个字典，没有门店、商品名称等维度字段。汇总回答默认只报：

| 字段 | 含义 |
| --- | --- |
| `销售数量` | 销售数量 |
| `实收金额` | 实收 |
| `毛利率` | 毛利率 |
| `门店库存` | 门店库存合计 |

其余字段（应收金额、成本额、毛利额、交易次数、期间天数、总部库存）只在用户问到时展示。总部库存仅问到才展示。

比率以 `total_summary` 里的值为准，不要用当前页自己重算。多商品一次查询时，`total_summary` 是所选商品合计在一起的数，按一份合计报即可，不要拆成每个商品各报一次（除非用户说「分别」走明细）。

## 示例

已得到商品编码 `10001234`。用户问三黄片今天卖了多少，没点门店、没说分别。先取当前日期，只查直营合计：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234"], store_type=["1"], size=1)
```

用户说「各直营店分别多少」：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234"], store_type=["1"], size=10)
```

已有门店编码 `1001`、租户 `1`、商品编码 `10001234`。用户问五星路店这个月这款药卖了多少：

```
get_store_goods_retail_info(start_date="2026-10-01", end_date="2026-10-20", goods_code=["10001234"], store_code=["1001"], tenant_id=1, size=10)
```

用户选定了两个规格 `10001234` 和 `10001235`，一次传入：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234", "10001235"], store_type=["1"], size=1)
```

已从区域树收集到「西南区」及其正常下级 `"101"`、`"102"`、`"103"`，查该区域该商品合计，直营和加盟一起：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234"], region_id=["101", "102", "103"], store_type=[], size=1)
```
