# 门店商品零售查询

工具：`get_store_goods_retail_info`

按商品查一段日期内的零售。行内数字是整段日期的合计，不是某一天，也不是单笔小票。

`goods_code` 必填，禁止传 `[]`。没有商品编码时不要调本工具。

- 用户点了商品名、还没有编码：先读 `/skills/erp-stock/goods.md`，调用 `get_goods_info`。
- 用户点了门店名、还没有门店编码：先读 `/skills/erp-shop-retail/shop.md`，调用 `get_shop_available_info`。
- 用户点了区域名、还没有区域 ID：先读 `/skills/erp-shop-retail/region.md`，调用 `get_region_tree_info`。
- 用户点了门店、没点任何商品：不要用本工具，改读 `/skills/erp-shop-retail/shop_retail.md`，用 `get_shop_retail_info`，可告知「动销品项数」。
- 用户只问库存、不问销售：不要用本工具，走库存 skill。

总部没有零售。不要传仓库 ID。不做排名，不要翻页排序后宣布卖得最好。

## 库存字段（重要）

「门店库存」「总部库存」都是**查询当天的当前库存**，不是销售日期区间内的历史库存。例如今天是 2026-10-23，查 10-01 至 10-10 的销售，行里的库存仍是 10-23 的数。回答时如用户可能误解，可简短说明是当前库存。

「总部库存」按商品维度只有一份。`is_store_summary=True` 时，同一商品在多家店各有一行，每行会重复显示同一个总部库存（例如三家店都显示 140，总部库存仍是 140，不是 140×3）。

- 展示多行时：总部库存按商品报一次即可，或注明各行相同、不要相加。
- 不要把各行的「总部库存」加总。
- `total_summary` 里的总部库存同样不要理解成「按行累加后的结果」；报总部库存时用单值，不要自行 × 门店数。
- 「门店库存」才是各店（或各类型汇总行）各自的当前库存，可以按行展示；加总门店库存时用 `total_summary` 的门店库存，不要自己把总部库存加进去。

## `is_store_summary`（是否按门店拆开）

| 值 | 含义 | 何时用 |
| --- | --- | --- |
| `False`（工具默认） | 不按具体门店拆。没有门店编码/名称/简称。同一商品在 `store_type=["1"]` 或 `["2"]` 时通常一行；`store_type=[]` 时直营、加盟各可能有一行（最多按门店类型拆开，不是按店） | 没点名门店、也没要求「各店/按门店分别」时。可省略不传。**禁止**在这种场景传 `True` |
| `True` | 按具体门店拆开。`data` 一行是「门店 × 商品」 | **仅**当用户要「各店」「按门店分别」，或点名了门店需要带门店字段的明细。没点门店且没说各店/分别时，绝不传 `True` |

不要把默认理解成「按门店汇总」。`True` = 按具体门店拆开；`False` = 不按具体门店拆，但仍可能按门店类型（直营/加盟）拆行。

## 参数

| 参数 | 含义 | 默认 | 取值 |
| --- | --- | --- | --- |
| `start_date` | 开始日期 | 必填 | `YYYY-MM-DD` |
| `end_date` | 结束日期 | 必填 | `YYYY-MM-DD` |
| `goods_code` | 商品编码列表 | 无，必填 | 字符串列表，元素是「商品编码」。至少一个。禁止 `[]` |
| `store_code` | 门店编码列表 | `[]` | 字符串列表。不限定门店时保持 `[]` |
| `store_type` | 门店类型 | `[]` | 见下方规则。未点名门店且用户没提加盟时必须显式传 `["1"]` |
| `tenant_id` | 租户 ID | 无 | 查过门店时用结果里的「租户ID」，整数。没有时不传 |
| `region_id` | 区域 ID 列表 | `[]` | 字符串列表，元素是区域树里的「区域ID」。不要转成整数。不按区域查时保持 `[]` |
| `is_store_summary` | 是否按门店拆开 | `False` | 见上方。未要求各店时可不传 |
| `current` | 页码 | `1` | 正整数 |
| `size` | 每页条数 | 工具默认 `20`，不要用 | 见下方搭配表。默认报当前页时传 `10`；仅用户明确只要合计且 `False` 时传 `1` |

`goods_code`、`size` 必须显式传入。未点名门店时的 `store_type` 也必须显式传入（默认只查直营时传 `["1"]`）。

日期按 `SKILL.md` 换算。用户没说日期时，开始和结束都是 `get_current_date` 返回的当天。

`goods_code`：

- 必须来自用户已确认的商品，或用户直接给的编码。单个也写成 `["10001234"]`。
- 用户选定多个时，放进同一个列表，一次调用。不要替用户挑规格。
- 商品工具里的 `goods_codes` 是单个字符串；本工具的 `goods_code` 是列表。不要混用类型。
- 禁止空列表。禁止传商品名称、通用名。

`store_code`：

- 点名了一家或多家，并且已经有编码：放进同一个列表。同一时段只调用一次。
- 没点名门店：保持 `[]`。
- 不要传门店名称，不要传仓库 ID。

`store_type`（商品零售专用，与门店零售不完全相同）：

- 用户没有明确要查加盟、也没有说直营和加盟都要：始终传 `["1"]`，只查直营。含按区域查、没点门店的场景。不要省略。
- 明确只看加盟：传 `["2"]`。
- 明确直营和加盟都要（或「全部类型」）：传 `[]`。
- 已经传了 `store_code`（点名具体门店）：传 `[]`，不再用类型过滤，避免把加盟点名店滤掉。

`region_id`：

- 没点名区域：保持 `[]`。
- 点名了区域：传入 `region.md` 收集到的全部字符串 ID。单个值也写成 `["101"]`，不要写成 `[101]`。
- 点名了具体门店：保持 `[]`，只用 `store_code`。不要和 `region_id` 一起传。

`size` 与 `is_store_summary` 搭配：

| 用户意图 | `is_store_summary` | `size` | 回答 |
| --- | --- | --- | --- |
| 某个/某几个商品卖了多少（不要各店） | `False`（可不传） | `10` | 报当前页 `data`。`page_info.total > 1` 时再报 `total_summary`；`total` 为 `1` 时只报那一行，不报合计 |
| 用户明确只要这几个商品的合计（不要各店、不要列行） | `False`（必须） | `1` | 只报 `total_summary`，不展示 `data` |
| 某商品各店分别 | `True` | `10` | 报当前页。`total > 1` 时再报 `total_summary` |
| 多个规格分别卖了多少（不要各店） | `False`（可不传） | `10` | 同第一行。默认直营时一行一个规格；`store_type=[]` 时同一规格可能直营、加盟各一行 |
| 点名门店 + 商品 | `True`（若只要数字不要门店字段，允许 `False`） | `10` | 报当前页。`total > 1` 时再报 `total_summary` |

硬性规则：

- 没点名门店、也没说各店/按门店分别：`is_store_summary` 绝不能为 `True`。
- 点了具体商品、未明确只要合计：一律 `size=10` 报当前页，不要用 `size=1` 只报汇总。
- `size=1` 仅允许：用户明确要合计，且 `is_store_summary=False`。
- 不要一次把 `size` 调大。用户要下一页时，`current` 加 1，`size` 仍为 `10`。

没有结果时不要改 `store_type`、`region_id`、`goods_code`、`is_store_summary` 或 `size` 重试。

## 调用流程

1. 确认 `start_date` 和 `end_date`。没说日期就用当天，调用前先取 `get_current_date`。
2. 确认已有商品编码。没有则先按 `goods.md` 查商品；多条命中先让用户选（可选多条），不要代选。
3. 确认有没有门店编码。有门店名称没有编码时，先查门店。
4. 确认有没有区域 ID。有区域名称没有 ID 时，先查区域树并收齐 ID。点了具体门店就不要再传 `region_id`。
5. 按上面的规则定 `store_type` 和 `is_store_summary`（没点门店且没说各店时不要传 `True`）。
6. 明确只要合计且 `False` 时传 `size=1`；其余传 `size=10`。
7. 调用 `get_store_goods_retail_info`。
8. 看 `status`、`data`、`total_summary`、`page_info`。
9. `size=1` 只整理 `total_summary`。`size=10` 先列当前页；仅当 `page_info.total > 1` 时再报 `total_summary`。

对比两个时段时，用同一套 `goods_code`、`store_code`、`store_type`、`region_id`、`is_store_summary` 和 `size` 各查一次，只更换日期。

## 返回结构

成功：`status` 为 `success`。

- `data`：当前页列表。`True` 时一行是一家店的一个商品；`False` 时无门店编码/名称/简称，按商品（及门店类型，若 `store_type=[]`）成行
- `total_summary`：本次查询全部页的合计。回答合计时用这里的数，不要只加总当前页。两种模式用法相同
- `page_info`：`current` / `size` / `pages` / `total`

`page_info.total` 是符合条件的行数。汇总查询即使 `size=1`，`total_summary` 仍是全部行的合计。

无数据：`status` 为 `error`，`message` 为「未找到门店商品零售信息」。直接说明这个日期和范围没有该商品的零售记录。不要改参数再查，也不要说系统故障。

未授权：`message` 为「未授权」。直接告诉用户，不要改参数再试。

日期范围写在回答顶部。结果里没有日期字段。

### `is_store_summary=True` 时的行（`data`）

「门店类型」可能仍是 `1` 或 `2`。回答时 `1` 写成直营，`2` 写成加盟。已经是中文就原样使用。

明细默认展示这些列：

| 字段 | 含义 |
| --- | --- |
| `门店编码` | 核对门店 |
| `门店简称` | 展示 |
| `门店类型` | 直营或加盟 |
| `商品名称` | 展示 |
| `规格/型号` | 展示 |
| `销售数量` | 销售数量 |
| `实收金额` | 实收 |
| `毛利率` | 毛利率 |
| `门店库存` | 该店当前库存（查询当天），默认展示。不是销售区间内的历史库存 |

当 `store_type=[]`（用户明确要直营和加盟一起）且当前页同时出现直营行与加盟行时：在表格之外，按**当前页**把销售数量、实收金额等按门店类型加总，告知直营、加盟分别多少，并写明「仅当前页，不是全部」。不要把当前页加总说成 `total_summary`。`store_type` 已是 `["1"]` 或 `["2"]` 时，不必再拆两边。

用户问到对应内容时，再使用其余字段：

| 字段 | 含义 |
| --- | --- |
| `门店名称` | 全称 |
| `商品编码` | 核对 |
| `通用名称` | 核对 |
| `基本单位` | 单位 |
| `剂型` | 展示 |
| `批准文号` | 核对 |
| `生产企业` | 核对 |
| `商品类型` | 展示 |
| `所属分类` | 展示 |
| `应收金额` | 应收 |
| `成本额` | 成本。仅用户问成本时展示 |
| `毛利额` | 毛利额。仅用户问毛利额时展示 |
| `交易次数` | 交易次数 |
| `总部库存` | 仅用户问总部库存时展示。当前库存，同一商品各店行数值相同，不要按行相加 |

### `is_store_summary=False` 时的行（`data`）

没有门店编码、门店名称、门店简称。仍保留「门店类型」：`store_type=[]` 时同一商品常有直营、加盟两行，必须用门店类型区分并分别展示。

明细默认展示这些列：

| 字段 | 含义 |
| --- | --- |
| `门店类型` | 直营或加盟。`store_type=[]` 时必展示 |
| `商品名称` | 展示 |
| `规格/型号` | 展示 |
| `销售数量` | 销售数量 |
| `实收金额` | 实收 |
| `毛利率` | 毛利率 |
| `门店库存` | 当前库存（查询当天），默认展示。不是销售区间内的历史库存 |

其余字段（商品编码、通用名称、应收、成本、毛利额、交易次数、总部库存等）只在用户问到时展示。总部库存仅问到才展示；`store_type=[]` 出现多行时，同一商品的总部库存不要按行相加。

### 合计（`total_summary`）

一个字典，没有门店、商品名称等维度字段。两种模式用法相同。汇总回答默认只报：

| 字段 | 含义 |
| --- | --- |
| `销售数量` | 销售数量 |
| `实收金额` | 实收 |
| `毛利率` | 毛利率 |
| `门店库存` | 门店当前库存的合计（仍是查询当天，不是历史） |

其余字段（应收金额、成本额、毛利额、交易次数、期间天数、总部库存）只在用户问到时展示。总部库存仅问到才展示；报总部库存时用单值，不要按门店数去乘。

比率以 `total_summary` 里的值为准，不要用当前页自己重算。`size=1` 且多商品一次查询时，`total_summary` 是所选商品合计在一起的数，按一份合计报即可。

## 示例

已得到商品编码 `10001234`。用户问三黄片今天卖了多少，没点门店、没说各店。报当前页（`is_store_summary` 可省略，勿传 `True`）：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234"], store_type=["1"], size=10)
```

用户明确只要这几个商品的合计：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234", "10001235"], store_type=["1"], size=1)
```

用户说「各直营店分别多少」：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234"], store_type=["1"], is_store_summary=True, size=10)
```

用户选定两个规格，要分别看销量、不要各店：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234", "10001235"], store_type=["1"], size=10)
```

已有门店编码 `1001`、租户 `1`、商品编码 `10001234`。用户问五星路店这个月这款药卖了多少：

```
get_store_goods_retail_info(start_date="2026-10-01", end_date="2026-10-20", goods_code=["10001234"], store_code=["1001"], tenant_id=1, is_store_summary=True, size=10)
```

已从区域树收集到「西南区」及其正常下级 `"101"`、`"102"`、`"103"`。用户没提加盟、没说各店，查该区域该商品，只查直营、报当前页：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234"], region_id=["101", "102", "103"], store_type=["1"], size=10)
```

用户明确要直营和加盟一起、且要各店分别：

```
get_store_goods_retail_info(start_date="2026-10-20", end_date="2026-10-20", goods_code=["10001234"], store_type=[], is_store_summary=True, size=10)
```
