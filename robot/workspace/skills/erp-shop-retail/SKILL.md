# 门店信息与零售

用门店工具查正常门店，用区域工具查区域树，用零售工具查这些门店在一段日期里的销售汇总。先按用户意图选工具，再调用。不要凭记忆编造门店编码、区域 ID、租户 ID 或金额。

零售结果是每家店一行，覆盖整个日期区间，没有按天的明细，也没有单笔小票。总部没有零售。不要改用仓库工具，不要把仓库 ID 当成门店编码。

## 先读哪份说明

只读即将调用的那一份，用绝对路径：

| 要做的事 | 工具 | 说明 |
| --- | --- | --- |
| 按门店名、简称、门店编码、助记码找门店 | `get_shop_available_info` | `/skills/erp-shop-retail/shop.md` |
| 按区域名称或区域编码找区域，并收集区域 ID | `get_region_tree_info` | `/skills/erp-shop-retail/region.md` |
| 按日期查零售汇总或门店明细 | `get_shop_retail_info` | `/skills/erp-shop-retail/retail.md` |

调用某个工具之前，先 `read_file` 对应说明（`limit=1000`）。

## 先定日期

零售工具的起止日期都必填，格式 `YYYY-MM-DD`。相对日期先调用 `get_current_date`，用返回字符串开头的日期，不要沿用本轮更早的日期。

- 用户没说日期：开始和结束都用当天。
- 昨天：昨天到昨天。
- 本周：本周一到今天。
- 上周：上周一到上周日。
- 本月：本月 1 日到今天。
- 上月：上月 1 日到上月最后一天。
- 用户给了明确起止：按用户说的日期。

回答第一句写明实际查询的日期范围。零售结果里没有日期字段。

## 先定汇总还是明细

没点名具体门店时，看用户要的是合计还是逐家数字：

- 「整体」「销售情况」「零售情况」「各门店」，以及没出现「分别」的问法：汇总。`size=1`，只采用 `total_summary`。`data` 里那一行门店不要当成结果。
- 出现「分别」：明细。`size=10`，列出当前页的门店行，合计仍用 `total_summary`。「各门店分别」按明细处理。

点名了一家或多家门店：走明细。先按下面的顺序拿到门店编码，再查零售。`size=10`。即使用户说「这家店整体怎么样」，也列出这家店的门店行。

`size` 每次都显式传入。汇总必须是 `1`，明细必须是 `10`。工具默认的 `20` 不要用。

## 查点名门店的零售

用户给出一家或多家门店（例如「五星路店和人民路店这个月的零售」）时，按这个顺序：

1. 读 `/skills/erp-shop-retail/shop.md`。每个名称单独调用一次 `get_shop_available_info`。
   - `keyword` 是模糊查询，可传门店名称、简称、门店编码或助记码。
   - 从结果取出「门店编码」和「租户ID」。
   - 一次关键词命中多家时，列出「门店简称」「门店编码」「门店类型」，让用户确认。不要猜，也不要带着不确定的编码去查零售。
2. 读 `/skills/erp-shop-retail/retail.md`，调用一次 `get_shop_retail_info`。
   - `store_code` 是字符串列表，把选定的编码放在一起，例如 `["1001","1002"]`。
   - `tenant_id` 用这些门店共同的「租户ID」。
   - 已经用 `store_code` 限定了门店时，`store_type` 保持 `[]`，`region_id` 也保持 `[]`。
   - `size=10`。

某一家没有查到门店，就停在这一步告诉用户，不要把空编码放进零售查询。

用户已经给了门店编码：跳过门店查询，直接把编码放进 `store_code`。

## 没点名门店，也没点名区域

不要先查门店，也不要查区域。`store_code` 和 `region_id` 都保持 `[]`，按范围传 `store_type`：

- 没说直营还是加盟：`["1"]`，只查直营。这个值必须显式传入，省略时接口会把直营和加盟查在一起。
- 明确只看加盟：`["2"]`。
- 直营和加盟都要：`[]`。

汇总时 `size=1`。用户说「分别」时 `size=10`，并按 `retail.md` 展示门店行。

没有结果时不要改 `store_type` 再查一遍。直营没有数据，就说明直营这段时间没有零售记录。

## 按区域查零售

用户点了区域名称或区域编码、没有点具体门店时，按这个顺序：

1. 读 `/skills/erp-shop-retail/region.md`，调用 `get_region_tree_info`。
   - 按「区域名称」或「区域编码」定位。同名多条先问用户。
   - 点名的区域状态是「停用」：告诉用户该区域已停用，无法查询。不要查零售。
   - 从选定区域收集「区域ID」：包含它自己，以及下面所有状态正常的下级，一直收到 `是否子节点` 为 `true` 的叶子。停用区域的 ID 不放进去。
   - 层级 `0` 的根区域同样处理：根区域自己的 ID 要传，下面所有正常区域的 ID 也要传。
2. 读 `/skills/erp-shop-retail/retail.md`，调用一次 `get_shop_retail_info`。
   - `region_id` 是字符串列表，放上一步收集到的全部 ID。不要把区域 ID 转成整数。
   - `store_code` 保持 `[]`。不要把区域内的门店编码再查一遍拼进去。
   - 用户没另外说直营或加盟：`store_type` 传 `[]`，直营和加盟一起查。明确只看直营时传 `["1"]`，只看加盟时传 `["2"]`。
   - 没说「分别」：`size=1`，只报 `total_summary`。说了「分别」：`size=10`，列出门店行。

用户同时点了具体门店和区域：按点名门店处理，`region_id` 保持 `[]`。

## 对比两个时段

「和上月比」「和上周比」以及任何两段时间的对比，拆成两次零售查询。每次一个日期区间，`store_code`、`store_type`、`region_id`、`size` 保持一致。两次都先读 `retail.md`。用两次的 `total_summary` 对照合计。明细对比再同时列出两次的当前页门店行。

这个查询不做排名。用户问哪家最高、卖得最好时，不要翻完全部页，也不要在本地排序后宣布名次。用户要看逐家数字时，按「分别」给当前页明细。

## 只查其中一层

- 只问门店编码、简称、类型、地址、电话、医保：只做门店查询。没有名称、简称、编码或助记码时，请用户补充，不要空查。
- 只问有哪些区域、区域层级、某个区域的上级：只做区域查询。
- 用户已经给了门店编码，只要零售：只查零售，`region_id` 保持 `[]`。
- 用户已经给了区域 ID，只要这个区域的零售：只查零售，按 `region.md` 的收集规则补上下级 ID。用户给的是单个区域 ID、没有区域树结果时，先查区域树再收集。
- 用户要按天的曲线或每一天一行：说明结果是每家店在整个区间的一行汇总，有销售的天数看「动销天数」。不要拆成每天一次查询。

## 回答要求

- 用中文表格或短列表，不要原样倒 JSON。
- 名称、编码、金额以工具结果为准。
- 第一句写明日期范围。
- 汇总默认只报 `total_summary` 的：应收金额、实收金额、折扣率、毛利率、交易次数、客单价、客品数。可用 `page_info.total` 说明覆盖多少家门店。
- 明细默认列：门店编码、门店简称、门店类型、应收金额、实收金额、折扣率、毛利率、交易次数、客单价、客品数。合计用 `total_summary` 的上述指标，不要把当前页加总当成全部。
- 零售行的「门店类型」若是 `1` 写成直营，`2` 写成加盟。
- `store_type=["1"]` 时说明是直营、不含加盟。`["2"]` 时说明是加盟、不含直营。`[]` 且没点名门店时说明含直营和加盟。点名门店时说明查的是这些门店。按区域查时说明区域名称。
- `status` 为 `error` 且消息是「未找到区域树信息」时，说明没有区域数据。用户点名的区域已停用时，说明该区域已停用，无法查询。
- 成本额、毛利额、折扣金额、销售数量、品单价、客品次、会员、动销、日均，只在用户问到时展示。问有销售的天数时用「动销天数」。
- 明细超过一页时，报 `page_info.total` 和 `pages`。用户要下一页再把 `current` 加 1，`size` 仍为 `10`。
- `status` 为 `error` 且消息是「未找到可用门店信息」或「未找到门店零售信息」时，说明当前条件没有命中。不要说系统故障。
- 消息是「未授权」时，直接告诉用户未授权，不要改参数重试。
